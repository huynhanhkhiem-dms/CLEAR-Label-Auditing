# CLEAR: Label Quality Auditing in Fixed Data Repositories

Public code and reproducibility materials for the manuscript **“Label Quality Auditing in Fixed Data Repositories with Random Verification and Finite-Sample FDR Control.”**

CLEAR separates two roles that are often conflated in label cleaning: a **frozen suspicion score** is used to rank likely errors, while an **independent simple-random verification sample** supplies correctness outcomes for finite-library conformal calibration and Benjamini–Hochberg selection.

## Repository contents

- `clear_core.py` — core CLEAR p-value, random-verification, biased-verification stress-test, BH, and evaluation primitives.
- `PMLB/reproduce_pmlb_main.py` — compact reproduction of the principal PMLB CLEAR and biased-verification experiment over the frozen 55-dataset manifest.
- `CIFAR10N/reproduce_cifar10n_main.py` — compact reproduction of the principal CIFAR-10N repeated-audit experiment.
- `scripts/download_cifar10n_labels.py` — downloads and SHA-256 verifies the official CIFAR-10N human labels.
- `scripts/build_cifar10_embeddings.py` — constructs the frozen 512-dimensional ImageNet ResNet-18 embeddings used by the CIFAR-10N runner.
- `scripts/verify_reported_results.py` — fast consistency check for compact result summaries and headline manuscript values.
- `PMLB/*.csv|json` and `CIFAR10N/*.csv|json` — frozen configuration, manifests, compact summaries, budget/downstream tables, and provenance metadata used for manuscript QA.

The repository intentionally does **not** redistribute the original PMLB, CIFAR-10, or CIFAR-10N datasets. They are obtained from their public source projects by the experiment/setup scripts.

## PMLB experiment

A Python environment matching the archived run is documented in `PMLB/environment.json` and `requirements-pmlb.txt`.

```bash
python -m pip install -r requirements-pmlb.txt
python PMLB/reproduce_pmlb_main.py --out runs/pmlb_main.csv
```

The script downloads public PMLB datasets and reproduces the main random-verification versus score-biased-verification analysis using the frozen dataset manifest and seeds reported in the study.

## CIFAR-10N experiment

Install the CIFAR dependencies, create a run directory, download the official human labels, and build frozen ResNet-18 embeddings before the audit run:

```bash
python -m pip install -r requirements-cifar10n.txt
python scripts/download_cifar10n_labels.py --root runs/cifar10n
python scripts/build_cifar10_embeddings.py --root runs/cifar10n
python CIFAR10N/reproduce_cifar10n_main.py --root runs/cifar10n
```

`CIFAR10N/embedding_meta.json` records the software/hardware provenance and SHA-256 of the representation used for the reported experiment. Exact floating-point hashes may differ across hardware/software stacks; the intended representation is defined by official CIFAR-10 training order, `torchvision.models.resnet18`, `IMAGENET1K_V1` weights, and the transform bundled with those weights.

## Reported-result artifacts

The compact tables in this repository are publication-facing summaries retained from the verified experiment package. Large record-level result files and long-run checkpoints are omitted from GitHub to keep the repository lightweight; the principal analyses can be regenerated by the reproduction scripts, and the archived record-level outputs are available from the corresponding author on reasonable request. The manuscript reports, among other results, PMLB CLEAR FDR 0.0442 at q=0.10 and a large deterioration under score-biased verification (FDR 0.3913), illustrating that verification design is part of the inferential procedure.

## Reproducibility notes

1. The complete suspicion-score vector is frozen before verification outcomes are used for calibration.
2. The valid CLEAR audit uses simple random sampling without replacement for verification.
3. The score-biased verification branch is a deliberately invalid comparator used to demonstrate calibration failure under a changed sampling mechanism.
4. Random seeds, verification budgets, model settings, dataset eligibility rules, and summary outputs are preserved in the repository.
5. Public-source benchmark data are not relicensed or redistributed here.
